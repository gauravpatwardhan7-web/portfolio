Context

Shell runs 22 in-house Petrel plugins — geoscience tools built on a vendor SDK that ships a deprecation release every year. Every release, engineers hand-patch each plugin against the SDK changes before subsurface teams can use it. I own product for this area.

The problem

Maintenance ran to roughly six weeks of engineering time per plugin, per release. The work is repetitive and low-judgment, but high-context: you need the SDK, the plugin, and a working definition of “still correct.” That makes it AI-shaped — and also AI-failure-shaped. A plausible-but-wrong patch inside a geoscience tool costs more than doing the patch by hand, so the hard part was never generation. It was verification.

What I built

A two-agent harness, specified the way I’d specify any product:

  • —Tools — the agents act on the codebase and the SDK through a defined surface, instead of emitting free-form suggestions a human has to transcribe.
  • —Skills — the SDK migration knowledge senior engineers carried in their heads, written down once as instructions the agents load every run.
  • —A test playbook — what to run, in what order, to prove a migration actually held.
  • —Acceptance criteria — an explicit definition of done, so output is measured against a standard rather than eyeballed by whoever is reviewing.

Where the product judgment was

  • 1Choosing the problem by cost, not by novelty. Annual, repetitive, 22 plugins wide — the arithmetic made the case before any demo did.
  • 2Designing for verification, not autonomy. The harness’s job is a change an engineer can check quickly and reject cheaply. The playbook and acceptance criteria are the product; generation is the easy half.
  • 3Fixing the structural cause in parallel. Discovery across all 22 plugins led me to scope an adapter pattern isolating SDK calls, so each annual release changes one layer, not the whole plugin. AI makes the recurring work cheaper; architecture makes less of it recur.
  • 4Proving it before scaling it. I took a 5-plugin pilot for approval rather than a 22-plugin mandate — a real sample, with a decision point attached.

Outcome

Maintenance fell from about six weeks to roughly one week per plugin, and the 5-plugin pilot was approved. The reusable asset isn’t the patch — it’s the harness and the written-down migration knowledge, which hold for next year’s release too.
